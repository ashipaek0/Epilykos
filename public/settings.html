🚀 Quick Start — 5 minutes to your first dashboard
1
Add a data source
Go to Data Sources → Modbus (or HA, MQTT, RS232, Dongle, BMS, REST). Enter connection details and pick a profile matching your hardware.
2
Map registers/fields to metric names
Click Load Profile Fields. Each row shows a device register — use the dropdown to pick a metric name (or keep the default). Save settings.
3
Build a dashboard
Open the Editor. Drag a Flow Card onto the canvas. Click Config on the block, then select which metrics feed each role (solar, consumption, battery, grid).
4
See live data
Data polls every 30s by default. Values update automatically. The Power Chart shows 24h history — it populates as polling continues.

💡 Prerequisite: You need at least one connected device (inverter, sensor, or external API). Start with the data source that matches your hardware.

📡 Data Source Guides — setup each type step by step
🏠 Home Assistant

What it's for: Pull sensor values from an existing Home Assistant instance over HTTP.

Required HA URL (e.g. http://192.168.1.50:8123)
Required Long-lived access token (HA → Profile → Security → Long-lived tokens)
Note Only sensor.* and binary_sensor.* entities are fetched
Note Binary sensors auto-convert on/off → 1/0

Steps:

  1. Go to Data Sources → Home Assistant
  2. Enter HA URL and token → click Fetch Entities to load your sensor list
  3. Click + Add Metric Mapping for each value you want
  4. Pick a metric name (e.g. grid_power) and an entity (e.g. sensor.shelly_em_grid_power)
  5. Set poll interval (30–60s recommended)
📨 MQTT

What it's for: Subscribe to MQTT topics from any broker (Mosquitto, EMQX, Tasmota devices, etc.).

Required Broker URL (e.g. mqtt://192.168.1.50:1883)
Optional Username and password if broker requires auth

Steps:

  1. Go to Data Sources → MQTT
  2. Enter broker URL → click Test Broker
  3. Use Discover Topics to find available topics, or enter manually
  4. Click + Add Metric Mapping → pick a metric name, enter the topic
🔌 Modbus (RTU / TCP)

What it's for: Direct serial (RS485/USB) or TCP connection to inverters and charge controllers.

Required Serial: /dev/ttyUSB0 (or similar), correct baud rate + unit ID
Required TCP: IP address + port (usually 502)
Required Select the correct profile for your hardware

🔌 RS232 (Serial ASCII / Binary)

What it's for: Direct serial connection to inverters using ASCII query/response or binary protocols.

Required USB-to-serial cable with correct driver (CH340, FTDI, CP2102)
Required User must be in the dialout group: sudo usermod -a -G dialout $USER

Profile → baud rate defaults:

ProtocolProfileDefault Baud
Voltronic QPIGSVoltronic / Axpert (QPIGS ASCII)2400
InfinisolarInfinisolar (alias → QPIGS)2400
SolaX AA55SolaX Pocket / X1 (AA55 Binary)9600
Victron VE.DirectVictron VE.Direct19200

Steps:

  1. Go to Data Sources → RS232
  2. Select serial port and baud rate (match profile defaults above)
  3. Pick a profile from the dropdown
  4. Click Load Profile Fields → map each field to a metric name
  5. Click Test RS232 to verify
📶 Dongle (WiFi Data Loggers)

What it's for: Inverters with built-in WiFi loggers (Solarman, Felicity TCP). Connects over your local network — no USB cable needed.

Required Logger IP address on your local network
Required Logger serial number (printed on device or sticker)
Required Correct profile for your inverter model

Steps:

  1. Go to Data Sources → Dongle
  2. Enter IP, port (default 8899 for Solarman, 502 for Felicity TCP), and serial number
  3. Pick a profile matching your inverter
  4. Click Load Profile Registers → map to metric names
  5. Click Test Connection to verify
🔋 BMS (Battery Management System)

What it's for: Direct connection to a BMS over serial (RS485/USB) for battery-level data.

Required Serial path and correct BMS address
Note Currently supports JBD / Xiaoxiang BMS protocol

Steps:

  1. Go to Data Sources → BMS
  2. Enter serial port path and BMS address
  3. Enable the device and save
🌐 External / REST API

What it's for: Pull data from any HTTP JSON API (weather services, energy monitors, custom endpoints).

Required URL returning JSON
Note Use dot notation for JSON paths: data.power, results[0].temperature

Example:

URL: https://api.weather.gov/stations/KNYC/observations/latest
JSON path → Metric:
properties.temperature.value → outdoor_temp
properties.relativeHumidity.value → outdoor_humidity

Steps:

  1. Go to Data Sources → External
  2. Enter URL, click + Add Metric Mapping for each value
  3. Enter JSON path and pick a metric name
🏷️ Metric Names — naming conventions and system roles

Metric names are the labels that identify your data throughout the system. Choose them carefully — they connect your hardware to the dashboard.

Conventions

  • Use lowercase with underscores: battery_voltage not BatteryVoltage
  • Be descriptive: pv1_power is better than solar
  • Use consistent suffixes: _power, _voltage, _current, _energy, _soc, _temp
  • Number multiple PV strings: pv1_power, pv2_power

System Roles (auto-mapped to dashboard)

The dashboard detects these metric names automatically. Using them lets blocks auto-connect without manual config:

How role mapping works

  1. Each dashboard block (e.g. Flow Card) specifies which role each metric plays: solar, consumption, battery, grid
  2. The role_metrics config (auto-populated from your blocks) maps roles → actual metric names
  3. The history system reads latest_metrics using this mapping to populate the history table and charts
  4. You can override roles in Settings → Solar → Metric Roles

🎨 Appearance & Theming

Go to Settings → Dashboard → Display for visual options.

  • Background: Solid color, gradient, or image URL
  • Transparent blocks: Makes block backgrounds see-through for a cleaner look with background images
  • Title & Logo: Set a dashboard title and upload a logo (appears top-left)
  • Favicon: Browser tab icon
  • Dark/Light theme: Toggle with the ☀️/🌙 button in the sidebar
💾 Backup & Restore

Go to Settings → Backup.

  • Manual backup: Click Download Backup to save your entire database to a .db file
  • Restore: Upload a backup file to replace all current data
  • Snapshots: Auto-created every 24 hours. Keeps the last 7 days. Click Restore on any snapshot to roll back
  • What's backed up: All config, metric history, dashboard layouts, and user-created metrics
🔧 Troubleshooting — common issues and fixes
🔌 Modbus Issues
SymptomLikely CauseFix
Connection refusedWrong IP or portVerify IP reachable: ping <ip>. Check port 502 open.
TimeoutWrong unit IDMost inverters use unit ID 1. Check your inverter manual.
No data on dashboardUnmapped registersClick Load Profile Fields and ensure each register has a metric name selected.
CRC / checksum errorsBaud rate mismatchMatch baud rate to your inverter (9600 for most, 2400 for Voltronic).
Port not foundUSB disconnected or driver missingCheck ls /dev/ttyUSB*. Install CH340/FTDI driver if needed.
Permission deniedNot in dialout groupsudo usermod -a -G dialout $USER then log out and back in.
All values show 0Wrong profile selectedMatch profile to your exact inverter model. Felicity profiles are model-specific.
🔌 RS232 Issues
SymptomLikely CauseFix
Permission deniedNot in dialout groupsudo usermod -a -G dialout $USER
Port not foundUSB cable disconnectedCheck ls /dev/ttyUSB* and reseat the cable
Read timeoutWrong baud rateMatch profile default: 2400 (Voltronic), 9600 (SolaX), 19200 (VE.Direct)
Partial / garbled dataElectrical noise or wrong wiringUse short, shielded cable. Check RX/TX/GND connections
No response at allWrong protocol profileConfirm your inverter protocol — Voltronic uses ASCII QPIGS, SolaX uses AA55 binary
📶 Dongle Issues
SymptomLikely CauseFix
TimeoutLogger not reachableCheck WiFi signal. Ping the logger IP. Check it's on the same subnet.
Checksum mismatchWrong serial numberSerial number is case-sensitive and must match the sticker exactly.
No dataWrong profileMatch the profile to your inverter model — Solarman ≠ Felicity TCP.
Connection refusedWrong portSolarman loggers use port 8899. Felicity TCP uses port 502.
📨 MQTT Issues
SymptomLikely CauseFix
Connection refusedBroker not running or wrong portCheck systemctl status mosquitto. Default port is 1883.
Auth failureWrong username/passwordVerify credentials in your MQTT broker config
No data appearingTopic not publishingUse mosquitto_sub -t "#" -v to verify the topic is publishing values
Values not updatingTopic mapped wrongEnsure the topic in settings exactly matches the MQTT topic (case-sensitive)
🔧 General Issues
SymptomLikely CauseFix
Dashboard shows zeros or emptyMetric name mismatchThe metric name in the block config must exactly match what your data source writes. Check Settings → Metrics for all current names.
Charts are emptyHistory not populated yetWait 2–3 poll cycles (60–90s). Charts need history data to render.
Solar values negative at nightInverter firmware quirkSome inverters report small negative PV values overnight. This is cosmetic — the flow card shows 0 for negative values.
Settings not savingSession expiredLog out and log back in. Settings save requires an active authenticated session.
Missing metrics dropdown optionsNo data sources polled yetMetric names appear after at least one poll cycle from any source. Check your sources are enabled and connecting.
📋 Debug Logs

Logs are at logs/energy-dashboard-*.log inside the Epilykos directory.

Set environment variable LOG_LEVEL=debug before starting for verbose output showing every Modbus/RS232 read, metric write, and poll cycle.

Docker: docker logs epilykos shows stdout. Add -e LOG_LEVEL=debug to your docker run/compose for detailed logging.
