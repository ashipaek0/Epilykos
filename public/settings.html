Quick Start — 5 minutes to your first dashboard

The quickest way in is the setup wizard: it finds common hardware, maps your readings to roles and builds a first dashboard. The steps below do the same by hand.

1
Add a data source
Go to Sources → Add source and pick your hardware: Modbus, WiFi dongle, RS232, BMS, Home Assistant, MQTT, Tuya or REST. Enter the connection details and pick the profile that matches your model.
2
Name the readings
Click Load Profile Fields (Modbus, RS232) or Load Profile Registers (WiFi dongle). Each row is one reading: keep the suggested metric name or type your own. Save.
3
Set the metric roles
In Metrics → Metric roles, say which metric is solar power, home use, battery, grid, generator and so on. Charts, tables, costs, savings and several blocks use these.
4
Build a dashboard
Open the layout editor, add blocks from the list on the left, and pick their metrics on each block's Data tab.

Readings refresh on their own: the main cycle runs every 30 seconds and each source has its own read interval. Charts and tables fill in as history builds up.

Data Source Guides — setup each type step by step
Home Assistant

What it's for: Pull sensor values from an existing Home Assistant instance over HTTP.

Required HA URL (e.g. http://192.168.1.50:8123)
Required Long-lived access token (HA → Profile → Security → Long-lived tokens)
Note Entities listed: sensor.*, binary_sensor.*, switch.*, light.*, climate.*, fan.*, cover.* and input_boolean.*
Note on/off states are kept as on/off; the grid status and switch blocks read them directly

Steps:

  1. Go to Sources → Home Assistant
  2. Enter HA URL and token → click Fetch Entities to load your sensor list
  3. Click + Add Metric Mapping for each value you want
  4. Pick a metric name (e.g. grid_power) and an entity (e.g. sensor.shelly_em_grid_power)
  5. Set poll interval (30–60s recommended)
MQTT

What it's for: Subscribe to MQTT topics from any broker (Mosquitto, EMQX, Tasmota devices, etc.).

Required Broker URL (e.g. mqtt://192.168.1.50:1883)
Optional Username and password if broker requires auth

Steps:

  1. Go to Sources → MQTT
  2. Enter broker URL → click Test Broker
  3. Use Discover Topics to find available topics, or enter manually
  4. Click + Add Metric Mapping → pick a metric name, enter the topic

Metric Names — naming conventions and system roles

Metric names are the labels that identify your data throughout the system. Choose them carefully — they connect your hardware to the dashboard.

Conventions

  • Use lowercase with underscores: battery_voltage not BatteryVoltage
  • Be descriptive: pv1_power is better than solar
  • Use consistent suffixes: _power, _voltage, _current, _energy, _soc, _temp
  • Number multiple PV strings: pv1_power, pv2_power

Metric roles

Roles tell Epilykos which of your metrics is which. Set them in Metrics → Metric roles (the setup wizard fills them in for you). They feed the history behind the power and energy charts, the daily and monthly tables, the energy day, flows and costs cards, and savings.

RoleUnitTypical metric names
Solar powerWpv_power, solar_power
Consumption (home use)Wload_power, ac_output_power
Battery charge / discharge powerWbattery_power (one signed value fills both), or separate charge and discharge metrics
Grid import / exportWgrid_power, grid_import, grid_export
Battery SOC%battery_soc
Solar voltageVpv_voltage, pv1_voltage
Daily solar, consumption, battery charge and discharge, grid import and exportkWh todaydaily_solar, pv_energy_today, … (reset at midnight by the inverter)
Generator power and daily generator energyW, kWh todaygenerator_power, generator_energy_today (inverters with a generator input)

No daily energy reading for a role? Combined metrics can work it out from power, or add several inverters' readings together.

Prices and savings — costs, generator and how savings are worked out

Set prices in Prices and savings. All prices are per kWh, in your currency.

  • Grid buy price and grid sell price: grid costs and export earnings in Costs and earnings
  • Generator buy price: for inverters with a generator input (fuel and upkeep per kWh); generator costs come from the daily generator role
  • Battery wear cost: charged on every kWh into or out of the battery

Solar savings

Each day's saving is that day's solar kWh × a price; today, week (from Monday), month and all time add the days up. Solar savings picks the price:

ChoicePrice per solar kWhExample (4 kWh solar, grid 0.30, generator 0.50)
At the grid buy price (default)Grid price4 × 0.30 = 1.20
By grid availabilityGrid price for solar made while the grid was on, generator price for solar made during an outage. Needs the grid status metric; without it, the grid price.Half made in an outage: 4 × (0.5 × 0.30 + 0.5 × 0.50) = 1.60
By what you actually boughtThe day's average price of the grid and generator energy bought: (grid kWh × grid price + generator kWh × generator price) ÷ (grid kWh + generator kWh). A day with neither: the grid price.Bought 2 kWh grid, 3 kWh generator: price 0.42, so 4 × 0.42 = 1.68

Set a generator price before choosing either generator-based method: with a price of 0, solar made during outages (or the generator part of the average) counts as worth nothing. Solar stored in the battery is valued when it was made, not when it was used.

Appearance & Theming

Go to Appearance for visual options.

  • Background: A colour for light mode and one for dark mode, or an image URL
  • Transparent blocks: Makes block backgrounds see-through for a cleaner look with background images
  • Title & logo: A dashboard title, and a logo image by URL (shown top left)
  • Favicon: The browser tab icon, by URL
  • Default dashboards: Which dashboard opens on computers and which on phones
  • Dark/Light theme: Choose Light, Dark or Auto at the bottom of the settings menu
Backup & Restore

Go to Backup and restore.

  • Manual backup: Click Download backup to save the whole database (settings, layouts and history) as a .db file
  • Restore: Restore from file… replaces everything with the backup
  • Snapshots: One is made automatically each day and the last 2 are kept. Click Restore on one to roll back
