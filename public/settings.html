1. Add a Data Source

Start in Data Sources and add at least one:

  • Home Assistant — URL + Long-Lived Access Token, click Fetch Entities, map metrics to entity IDs.
  • MQTT — broker URL (e.g. mqtt://192.168.1.50:1883), map topics to metric names.
  • Modbus — pick a profile (SRNE, Growatt, Deye, Victron), configure TCP or serial.
  • Inverter Dongle — direct TCP connection to your inverter's WiFi module. Supports Solarman V5, plain Modbus TCP, and Growatt push mode. See step below for details.
  • External REST — any HTTP API returning JSON. Map JSON paths to metrics.
  • Bluetooth BMS — requires the BMS bridge. Scan for devices, select MAC address.

0. Inverter Dongle Setup

Connect directly to your inverter's WiFi dongle without cloud services, Home Assistant, or any intermediary.

Setup steps:

  • Go to Data Sources → Dongle, click + Add Dongle Instance.
  • Give it a name (e.g. "SRNE Inverter").
  • Pick a Profile matching your inverter brand — this auto-fills the transport type, port, and Modbus unit ID.
  • Enter the dongle's Host / IP Address (e.g. 192.168.1.55).
  • Port and Modbus Unit ID are pre-filled from the profile — change only if your dongle uses non-standard values.
  • For Solarman V5 dongles: enter the Logger Serial Number (printed on the dongle label, usually 10 digits).
  • Optional: set a Metric Prefix (e.g. inverter1_) if you have multiple inverters to avoid metric name collisions.
  • Click Test Connection — a successful test returns a raw register value.
  • Click Save All Settings at the bottom of the page.

Transport types:

  • Solarman V5 (port 8899) — used by SRNE, Deye, SunSynk WiFi dongles. Requires the logger serial number for authentication. Opens a new TCP connection each poll cycle.
  • Modbus TCP (port 8899 or 502) — used by Sofar LSE-3 and Voltronic/Axpert dongles. Plain Modbus TCP — no serial number needed.
  • Growatt (TCP Server) (port 5279) — the dongle pushes data to Epilykos. You must reconfigure the dongle via its web UI at http://<dongle-ip>: change "Server Address" from server.growatt.com to your Epilykos host IP.

Polling behaviour:

  • Each enabled instance polls on its own interval (default 30s).
  • Registers are grouped into contiguous ranges and read in bulk — one TCP round-trip per range.
  • After 5 consecutive failures, the poll interval doubles (max 5 minutes) to reduce load on an unreachable dongle. It resets on the next successful poll.

2. Create & Map Metrics

Metric names identify your data. Mapping an entity/topic auto-creates the metric. Create custom ones in the Metrics tab.

Common names: solar consumption battery_soc battery_voltage grid_import grid_export. Binary sensors (on/off) auto-convert to 1/0.

3. Build Your Dashboard

Use the Editor (/editor) for visual layout — drag blocks from the palette, arrange freely, resize. Or use Dashboard settings to add/remove blocks and configure metrics per block.

Each block's Config button lets you pick which metrics feed it. Click Save All Settings when done.

4. Solar Forecast

In Solar Forecast: enable, enter latitude/longitude and system capacity (kWp). Add a Solcast API key for high accuracy, or leave blank for free Open-Meteo.

5. Grid Status Tracking

In Dashboard settings, enter your grid status metric name (e.g. grid_status). Epilykos tracks ON/OFF state, computes uptime hours (day/week/month/year) and the 24h timeline bar.

6. Appearance

Dashboard → Display: background colours (light/dark), background image, transparent blocks, title, logo, favicon. Savings: currency and rate per kWh.

7. Desktop & Mobile

Create separate layouts. In Dashboard, set the default tab for desktop and mobile — Epilykos auto-switches by screen width.

Tips

  • Blocks support multiple instances — add the same type twice with different metrics.
  • Use the lock/unlock button on the dashboard to prevent accidental drags.
  • Export your layout as JSON for backup or sharing.

8. Troubleshooting

Dongle connection errors:

  • "timeout" — the dongle didn't respond within 8 seconds. Check the IP address is reachable from the Epilykos host. Try ping <dongle-ip> from the server. Verify the port number matches your dongle model.
  • "connection refused" — the dongle's TCP port isn't open. Some dongles need a factory reset or firmware update to enable the Modbus TCP port.
  • "checksum mismatch" — data corruption on the wire. Usually transient; the next poll will succeed. If persistent, the serial number may be wrong (Solarman V5) or the profile doesn't match your inverter's register layout.
  • "Modbus exception 2" — illegal data address. The register in the profile doesn't exist on your inverter model. You may need a custom profile with the correct register map for your firmware version.
  • No data appearing on dashboard — check the metric names in Metrics tab match what the profile outputs. If you set a prefix, the metric name will be prefix + metric_name (e.g. inverter1_solar_power).
  • Growatt dongle not sending data — verify the dongle's web UI points to the Epilykos IP on port 5279. The dongle pushes data roughly every 5 minutes. Ensure no firewall blocks inbound port 5279.

Debug logs:

  • The server writes structured logs to logs/energy-dashboard-YYYY-MM-DD.log.
  • Set LOG_LEVEL=debug in your .env file and restart to see per-poll metrics and timing: LOG_LEVEL=debug node server.js.
  • Dongle log lines are prefixed with [dongle] — grep for them: grep '\[dongle\]' logs/energy-dashboard-*.log.
  • Each successful poll logs: [dongle] InstanceName: N metrics in Xms.
  • Each failed poll logs: [dongle] InstanceName: poll failed — reason.
  • Use docker compose logs -f epilykos for real-time logs in Docker deployments.
