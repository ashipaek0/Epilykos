Quick Start — 5 minutes to your first dashboard
1
Add a data source
Go to Sources → Add source → Modbus (or Home Assistant, MQTT, RS232, dongle, BMS, REST). Enter connection details and pick a profile matching your hardware.
2
Map registers/fields to metric names
Click Load Profile Fields. Each row shows a device register — use the dropdown to pick a metric name (or keep the default). Save settings.
3
Build a dashboard
Open the Editor. Drag a Flow card onto the layout. Select the block, then pick which metrics feed each role on its Data tab (solar, consumption, battery, grid).
4
See live data
Data polls every 30s by default. Values update automatically. The Power Chart shows 24h history — it populates as polling continues.

Prerequisite: You need at least one connected device (inverter, sensor, or external API). Start with the data source that matches your hardware.

Data Source Guides — setup each type step by step
Home Assistant

What it's for: Pull sensor values from an existing Home Assistant instance over HTTP.

Required HA URL (e.g. http://192.168.1.50:8123)
Required Long-lived access token (HA → Profile → Security → Long-lived tokens)
Note Only sensor.* and binary_sensor.* entities are fetched
Note Binary sensors auto-convert on/off → 1/0

Steps:

  1. Go to Sources → Home Assistant
  2. Enter HA URL and token → click Fetch Entities to load your sensor list
  3. Click + Add Metric Mapping for each value you want
  4. Pick a metric name (e.g. grid_power) and an entity (e.g. sensor.shelly_em_grid_power)
  5. Set poll interval (30–60s recommended)
MQTT

What it's for: Subscribe to MQTT topics from any broker (Mosquitto, EMQX, Tasmota devices, etc.).

Required Broker URL (e.g. mqtt://192.168.1.50:1883)
Optional Username and password if broker requires auth

Steps:

  1. Go to Sources → MQTT
  2. Enter broker URL → click Test Broker
  3. Use Discover Topics to find available topics, or enter manually
  4. Click + Add Metric Mapping → pick a metric name, enter the topic
Modbus (RTU / TCP)

What it's for: Direct serial (RS485/USB) or TCP connection to inverters and charge controllers.

Required Serial: /dev/ttyUSB0 (or similar), correct baud rate + unit ID
Required TCP: IP address + port (usually 502)
Required Select the correct profile for your hardware

RS232 (Serial ASCII / Binary)

What it's for: Direct serial connection to inverters using ASCII query/response or binary protocols.

Required USB-to-serial cable with correct driver (CH340, FTDI, CP2102)
Required User must be in the dialout group: sudo usermod -a -G dialout $USER

Profile → baud rate defaults:

ProtocolProfileDefault Baud

InfinisolarInfinisolar (alias → QPIGS)2400
SolaX AA55SolaX Pocket / X1 (AA55 Binary)9600
Victron VE.DirectVictron VE.Direct19200

Steps:

  1. Go to Sources → RS232
  2. Select serial port and baud rate (match profile defaults above)
  3. Pick a profile from the dropdown
  4. Click Load Profile Fields → map each field to a metric name
  5. Click Test RS232 to verify
Dongle (WiFi Data Loggers)

What it's for: Inverters with built-in WiFi loggers (Solarman, Felicity TCP). Connects over your local network — no USB cable needed.

Required Logger IP address on your local network
Required Logger serial number (printed on device or sticker)
Required Correct profile for your inverter model

Steps:

  1. Go to Sources → WiFi dongle
  2. Enter IP, port (default 8899 for Solarman, 502 for Felicity TCP), and serial number
  3. Pick a profile matching your inverter
  4. Click Load Profile Registers → map to metric names
  5. Click Test Connection to verify
BMS (Battery Management System)

What it's for: Direct connection to a BMS over serial (RS485/USB) for battery-level data.

Required Serial path and correct BMS address
Note Currently supports JBD / Xiaoxiang BMS protocol

Steps:

  1. Go to Sources → BMS
  2. Enter serial port path and BMS address
  3. Enable the device and save
External / REST API

What it's for: Pull data from any HTTP JSON API (weather services, energy monitors, custom endpoints).

Required URL returning JSON
Note Use dot notation for JSON paths: data.power, results[0].temperature

Steps:

  1. Go to Sources → REST API
  2. Enter URL, click + Add Metric Mapping for each value
  3. Enter JSON path and pick a metric name
Metric Names — naming conventions and system roles

Metric names are the labels that identify your data throughout the system. Choose them carefully — they connect your hardware to the dashboard.

Conventions

  • Use lowercase with underscores: battery_voltage not BatteryVoltage
  • Be descriptive: pv1_power is better than solar
  • Use consistent suffixes: _power, _voltage, _current, _energy, _soc, _temp
  • Number multiple PV strings: pv1_power, pv2_power

Appearance & Theming

Go to Appearance for visual options.

  • Background: Solid color, gradient, or image URL
  • Transparent blocks: Makes block backgrounds see-through for a cleaner look with background images
  • Title & Logo: Set a dashboard title and upload a logo (appears top-left)
  • Favicon: Browser tab icon
  • Dark/Light theme: Choose Light, Dark or Auto at the bottom of the settings menu
Backup & Restore

Go to Backup and restore.

  • Manual backup: Click Download Backup to save your entire database to a .db file
  • Restore: Upload a backup file to replace all current data
  • Snapshots: Auto-created every 24 hours. Keeps the last 2. Click Restore on any snapshot to roll back

CRC / checksum errorsBaud rate mismatchMatch baud rate to your inverter (9600 for most, 2400 for Voltronic).

Permission deniedNot in dialout groupsudo usermod -a -G dialout $USER then log out and back in.
